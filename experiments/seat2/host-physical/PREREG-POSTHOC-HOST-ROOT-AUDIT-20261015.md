### Registered Seat 2 adversarial controls, requiring FAIL or explicit custody limitation

1. Flip an original model HBP source byte => **pinned original HBP SHA fails**, independently of telemetry claims.
2. Alter a model console log byte and leave its parent witness unchanged => **log SHA validation fails**.
3. Overwrite process CPU time or RSS with zero => **physical observation plausibility test fails**.
4. Change host witness reported OS family => **OS expected binding fails**.
5. Change one CPU time in witness while leaving the separately downloaded parity JSON fixed => **cross-host parity fails**.
6. Falsify a CPU measurement while also forging the parity receipt to match the new value => this may still be locally self-consistent. An unsigned, user-editable witness + parity report is **not independently authentic hardware telemetry**; record `HOST_CUSTODY_UNAUTHENTICATED`, regardless of any positive unit tests. Do not describe an unsigned host JSON SHA256 as a signature.
7. Authentic independently observed CPU time/RSS and the underlying semiconductor/electrical operation are relevant **physical evidence**. Do not dismiss a host process as merely abstract. But CPU/RSS counters are not direct oscilloscope amperes, photodiode photon counts, acoustically calibrated phonons or persistence of photons across an actual source-off period.
